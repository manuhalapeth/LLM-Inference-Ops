# Incident report: checkout errors

At 09:12 UTC on Tuesday, the payments API began returning elevated error rates. Monitoring showed the p99 latency of the checkout service climbing from its usual 180 milliseconds to over 4 seconds within six minutes. The on-call engineer was paged at 09:15 and joined the incident channel at 09:19. Initial investigation focused on the database, because the dashboard showed connection pool saturation on the primary Postgres instance. However, query latency on the database itself remained normal, which suggested the pool was exhausted by connections being held open rather than by slow queries.

At 09:31 a second engineer noticed that a deployment of the fraud-scoring service had gone out at 09:08. The new version added a synchronous call to an external risk provider inside a database transaction. When the external provider slowed down, each checkout request held its database connection for the full duration of the external call. With 200 connections in the pool and the external call taking 3 to 5 seconds, the pool was exhausted at roughly 50 requests per second, well below normal peak traffic of 140 requests per second.

The team rolled back the fraud-scoring deployment at 09:38. Error rates returned to baseline by 09:44, and the connection pool drained within two minutes of the rollback. In total, approximately 11 percent of checkout attempts failed during the 32-minute window, and an estimated 4,100 customers saw an error page. No payments were double-charged, because the idempotency keys on the payment processor prevented duplicate captures.

Follow-up actions agreed in the review: move the external risk call outside the database transaction; add a timeout of 800 milliseconds with a fallback score; add an alert on connection pool utilization above 80 percent; and require load tests for any change that adds a network call to the checkout path. The review also noted that the deployment pipeline had no automated canary analysis, so the regression reached 100 percent of traffic within two minutes of release.
